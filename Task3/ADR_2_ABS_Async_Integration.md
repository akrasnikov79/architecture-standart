## Асинхронная интеграция Deposit Service и АБС (L2 Container)

### Context and Problem Statement
Подача заявок на депозит из онлайн-каналов (ИБ и Сайт) может привести к лавинообразному росту количества запросов (в особенности в период маркетинговых акций). Целевая АБС (Oracle/Delphi) умеет масштабироваться только вертикально и уязвима к пиковым нагрузкам. Прямая синхронная запись транзакций из ИБ в АБС рискует деградировать производительность ядра. Нужно определить паттерн интеграции.

### Considered Options
1. Синхронная интеграция через REST API к ядру АБС (HTTP POS POST).
2. Асинхронная интеграция через публикацию событий в брокер сообщений (Kafka).
3. Асинхронная интеграция через промежуточные буферные таблицы (Database Link).

### Decision Outcome
Выбран вариант 2 (Асинхронная интеграция через брокер сообщений Kafka).
Хотя `FURPS+.md` указывал Kafka как перспективу, именно паттерн Event-driven architecture надежно демпфирует пики нагрузок, снимая с АБС необходимость синхронно отвечать онлайн-каналам. `Deposit Service` будет публиковать событие `ApplicationCreatedEvent`, а интеграционный слой АБС — вычитывать его со своей скоростью.

### Consequences
- АБС гарантированно защищена от неконтролируемых пиков.
- Переход к eventual consistency (заявка в ИБ подтверждается как "Принята", а статус "Открыто" доставляется позже).
- Необходима развертка кластера Kafka или использование существующего брокера для продуктивной эксплуатации.

### Confirmation
На `C4_Containers.md` связь от ИБ к АБС помечена как "Публикация заявки в очередь (Async)", а спецификация события зафиксирована в `abs-integration-asyncapi.yaml`.

### Pros and Cons of the Options

#### Option 1: Синхронная интеграция REST API
Good, because клиент получает мгновенный ответ о результате открытия.
Bad, because АБС будет жестко зависеть от нагрузки на фронтенд (отсутствует fault tolerance).

#### Option 2: Kafka (Асинхронный паттерн) (Выбран)
Good, because гарантированная доставка и сглаживание пиков.
Good, because снимается прямое связывание ИБ и ядра АБС.
Bad, because клиенту нужно реализовывать UI-индикацию ожидания.

#### Option 3: Буферные таблицы БД
Good, because простота реализации без новых инфраструктурных компонентов.
Bad, because антипаттерн интеграции (Integration Database), высокая связность схемы данных.
