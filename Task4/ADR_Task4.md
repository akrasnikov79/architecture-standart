### **Название задачи:** Передача актуальных ставок в партнерский кол-центр
### **Автор:** Архитектор (Antigravity)
### **Дата:** 12.03.2026

### **Функциональные требования (Use Cases)**
|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
| 1 | АБС, Почтовый шлюз | Экспорт ставок | АБС (или промежуточный сервис) ежедневно формирует файл со ставками и отправляет его в партнерский КЦ. |
| 2 | Система Партнерского КЦ | Импорт ставок | Внешняя система получает файл, парсит его и обновляет ставки в своей БД. |
| 3 | Сотрудник Партнерского КЦ, Клиент | Консультация | Сотрудник видит актуальные ставки в своей системе и консультирует клиента по телефону. |
| 4 | Сотрудник Внутреннего КЦ | Просмотр ставок | Сотрудник внутреннего КЦ видит ставки напрямую в CRM банка (интеграция с АБС). |

### **Нефункциональные требования**
|**№**|**Требование**|
| :-: | :- |
| 1 | **Безопасность:** Файл со ставками не содержит персональных данных, но является коммерческой информацией. Должен передаваться по защищенному каналу (например, шифрованный ZIP-архив по Email). |
| 2 | **Ограничения:** Внешняя система партнера не поддерживает API и защищенные файловые протоколы (SFTP). Передача файла возможна только через Email или ручную загрузку на защищенный портал. |

### **Решение**
Учитывая ограничения партнера (невозможность API и SFTP), предлагается реализовать асинхронную пакетную интеграцию на базе защищенной электронной почты (Secured Email / S/MIME) или автоматизированной выгрузки:
1. **АБС** выполняет ежедневную джобу (PL-SQL), выгружающую актуальную матрицу ставок в формате CSV/Excel.
2. Файл шифруется (с использованием PGP или паролированного архива).
3. Интеграционный слой АБС (Java Spring Boot) отправляет этот файл по расписанию (или по триггеру изменения) на выделенный почтовый ящик партнерского КЦ через корпоративный SMTP-сервер.
4. Партнерский КЦ на своей стороне реализует скрипт, читающий почтовый ящик, расшифровывающий файл и импортирующий данные в БД своей системы.
5. Для **внутреннего кол-центра** (CRM на React/Spring) реализуется интеграция на чтение с АБС или Deposit Service, чтобы операторы видели ставки онлайн.

Относительно C4 Контекста: добавляется новая связь `[АБС / Integr. Layer] -> (SMTP) -> [Почта партнера] -> [Система Партнерского КЦ]`.

### **Альтернативы**
1. **Предоставить партнерам веб-портал для скачивания (Web Portal / B2B).** Это более безопасно, но требует разработки веб-интерфейса загрузки авторизованным пользователем. Выбрана отправка по email как наиболее дешевый и быстрый MVP-вариант.
2. **Ручная отправка писем сотрудником Бэк-офиса.** Не требует разработки, но обременяет бизнес-подразделение операционной рутиной и ведет к человеческим ошибкам (забыли отправить).

**Недостатки, ограничения, риски**
- **Риск рассинхронизации:** Ставки обновляются ежедневно, но в течение дня могут измениться. Партнеры могут консультировать по устаревшим ставкам до следующей отправки файла.
- **Недостаток:** Email — не самый надежный транспорт для системной интеграции (риск попадания в спам, задержки почтовых серверов). Плюс необходимость управления ключами/паролями.
