## Обмен данными о ставках с Партнерским Кол-центром (L2 Container)

### Context and Problem Statement
Банк привлекает Партнерский кол-центр для обзвона потенциальных клиентов и продаж депозитных продуктов. Партнерам требуются актуальные тарифы и ставки каждый день. Проблема в том, что система Партнерского КЦ закрыта, не поддерживает интеграцию по API и не имеет доступа по SFTP. Требуется выбрать транспорт для надежной ежедневной передачи экспорт-модели ставок с учетом требований информационной безопасности.

### Considered Options
1. Ручная отправка файла ставок сотрудниками Бэк-офиса банка на почту куратора в КЦ Партнера.
2. Автоматическая пакетная интеграция через защищенную электронную почту (шифрованный Excel/CSV файл по SMTP/S-MIME).
3. B2B Веб-портал банка (Партнер заходит и скачивает файл руками).

### Decision Outcome
Выбран вариант 2 (Автоматическая выгрузка зашифрованного файла через SMTP).
Учитывая ограничения на стороне партнера, этот способ обеспечивает автоматизацию (исключает ручной труд менеджеров банка) и удовлетворяет компромиссным требованиям ИБ (использование шифрования PGP или S/MIME поверх файловых вложений). 

### Consequences
- Сотрудники бэк-офиса избавлены от рутины ручной выгрузки.
- Файлы могут теряться в спам-фильтрах, потребуется мониторинг доставки.
- Сохраняется риск рассинхронизации ставок в течение дня, так как интеграция выполняется пакетом (например, раз в сутки).
- Интеграционный слой АБС должен быть доработан для генерации файла, шифрования и вызова SMTP-клиента.

### Confirmation
Решение зафиксировано в модели C4 и в архитектурном плане как добавление связи `[ABS Integration Layer] -> (SMTP) -> [System of Partner Call Center]`.

### Pros and Cons of the Options

#### Option 1: Ручная отправка
Good, because нулевая стоимость разработки.
Bad, because высокий риск человеческой ошибки (забыли отправить) и рутинная нагрузка на бизнес.

#### Option 2: Авто-отправка Email с шифрованием (Выбран)
Good, because автоматизирует процесс и адаптируется к тех. ограничениям партнера (Email есть у всех).
Good, because безопасность на базовом уровне обеспечивается шифрованием файла.
Bad, because Email менее надежен, чем API, сложно обрабатывать ошибки доставки.

#### Option 3: B2B Веб-портал
Good, because высокая безопасность и контроль скачивания.
Bad, because требуется дорогостоящая разработка веб-портала авторизации для партнеров.
