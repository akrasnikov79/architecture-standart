# Требования к системе открытия депозитов банка «Стандарт» (FURPS+)

| Код    | Требования                                                                                                                                                                                          | Комментарий                                                                                                                        |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **F**  | **Функциональные (Functionality)**                                                                                                                                                                  |                                                                                                                                    |
| F1     | Витрина депозитов на сайте: отображение списка доступных депозитов с актуальными ставками для новых клиентов.                                                                                       | MVP. Данные о ставках берутся из АБС (после переноса из Excel).                                                                    |
| F2     | Витрина депозитов в интернет-банке: отображение списка депозитов с актуальными ставками и персонализированными предложениями для конкретного клиента.                                               | Персонализация на основе данных клиента в АБС (сумма на счетах, история).                                                          |
| F3     | Подача заявки на депозит на сайте: клиент вводит ФИО и номер телефона. Заявка передаётся в систему кол-центра (CRM).                                                                                | Передача чувствительных данных — требуется шифрование (см. +R1).                                                                   |
| F4     | Интеграция сайта с CRM кол-центра: менеджер кол-центра видит заявку с сайта, изучает её и перезванивает клиенту, может предложить особые условия.                                                   | Архитектурно-значимое: требуется интеграция между сайтом (PHP/React) и CRM (Java Spring Boot).                                     |
| F5     | Подача заявки на депозит в интернет-банке: клиент указывает счёт списания и сумму депозита.                                                                                                         |                                                                                                                                    |
| F6     | Подтверждение операции открытия депозита в интернет-банке с помощью СМС-кода (OTP).                                                                                                                 | Архитектурно-значимое: функционал СМС есть в ядре интернет-банка, но реализация — силами банка, без подрядчика (см. +R5).          |
| F7     | Ведение и расчёт ставок по депозитам в АБС: перенос расчёта ставок из Excel-файлов в АБС. Доступ для бэк-офиса депозитов и бэк-офиса кредитов.                                                      | Архитектурно-значимое: отказ от ручного Excel-процесса. Необходима доработка АБС (Oracle PL/SQL).                                  |
| F8     | Обработка онлайн-заявки менеджером бэк-офиса депозитов: подтверждение условий и ставки в АБС.                                                                                                       | MVP: ручная обработка. Целевое состояние — полная автоматизация.                                                                   |
| F9     | СМС-уведомление клиенту после подтверждения ставки менеджером бэк-офиса.                                                                                                                            | АБС → СМС-шлюз → телеком-оператор → клиент.                                                                                        |
| F10    | СМС-уведомление клиенту после открытия депозита.                                                                                                                                                    | АБС → СМС-шлюз → телеком-оператор → клиент.                                                                                        |
| **U**  | **Удобство использования (Usability)**                                                                                                                                                              |                                                                                                                                    |
| U1     | Интерфейс сайта и интернет-банка должен соответствовать корпоративной дизайн-системе банка: привычные цвета, брендированные элементы.                                                               | Явное требование бизнеса.                                                                                                          |
| U2     | Максимально удобный и интуитивно понятный UX при открытии депозита.                                                                                                                                 | Явное требование бизнеса: «интерфейс работы будет максимально удобным для клиента».                                                |
| U3     | Минимальное количество шагов для подачи заявки: на сайте — 2 поля (ФИО + телефон); в Интернет-банк — выбор счёта + сумма + подтверждение СМС.                                                       | Дополнительное: снижение барьера входа для привлечения клиентов из молодых категорий.                                              |
| U4     | Информативные СМС-уведомления о статусе заявки: клиент понимает текущий этап обработки.                                                                                                             | Дополнительное: повышение доверия клиентов к онлайн-каналу, снижение нагрузки на кол-центр (меньше звонков «где моя заявка?»).     |
| **R**  | **Надёжность (Reliability)**                                                                                                                                                                        |                                                                                                                                    |
| R1     | Доступность онлайн-сервисов 24/7 с SLA 99,9%.                                                                                                                                                       | Архитектурно-значимое: требует балансировки нагрузки и отказоустойчивой архитектуры.                                               |
| R2     | Работоспособность интернет-банка при сбое основного ЦОД: переключение на резервный ЦОД.                                                                                                             | Архитектурно-значимое: развёртывание active-passive или active-active контура в резервном ЦОД.                                     |
| R3     | Равномерное горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД.                                                                                            | Архитектурно-значимое: относится к Интернет-банку, API-шлюзам, новым микросервисам. АБС — только вертикально (см. +R4).            |
| R4     | При недоступности АБС новые заявки не должны теряться: буферизация через очередь сообщений (Kafka).                                                                                                 | Архитектурно-значимое: гарантия доставки (at-least-once). Команда АБС предупреждает о перегрузке БД.                               |
| R5     | Согласованность данных между Интернет-банком и АБС: модель eventual consistency при асинхронном взаимодействии.                                                                                     | Дополнительное: следствие асинхронной интеграции через Kafka. Необходимы механизмы компенсации и идемпотентности.                  |
| **P**  | **Производительность (Performance)**                                                                                                                                                                |                                                                                                                                    |
| P1     | Отклик системы по всем операциям — миллисекунды. Текущая проблема: загрузка справочных данных >1 сек.                                                                                               | Архитектурно-значимое: требуется кэширование справочников.                                                                         |
| P2     | Исключение прямой синхронной работы интернет-банка с API/БД АБС в новом процессе.                                                                                                                   | Архитектурно-значимое: база АБС перегружена, онлайн-заявки усугубят ситуацию.                                                      |
| P3     | Кэширование каталога депозитов и справочных данных: снижение нагрузки на БД, ускорение отклика.                                                                                                     | Архитектурно-значимое: решает текущую проблему загрузки >1 сек. Кэш обновляется периодически или по событию.                       |
| P4     | Асинхронное взаимодействие Интернет-банка → АБС через очередь сообщений (Kafka): заявки обрабатываются без блокировки пользователя.                                                                 | Архитектурно-значимое: развязка систем, защита АБС от пиковых нагрузок.                                                            |
| **S**  | **Поддерживаемость (Supportability)**                                                                                                                                                               |                                                                                                                                    |
| S1     | Разработка исчерпывающей документации на новые компоненты и API для дальнейшего расширения системы.                                                                                                 | Требование заказчика.                                                                                                              |
| S2     | Использование существующих в банке технологий: MS SQL, Oracle, C#/.NET, Java Spring Boot, React.js.                                                                                                 | Архитектурно-значимое: минимизация Time-to-Market, использование имеющейся экспертизы.                                             |
| S3     | Выделение сервиса депозитов из монолита Интернет-банка в микросервис (в рамках задачи открытия депозитов).                                                                                          | Архитектурно-значимое: первый шаг к микросервисной архитектуре Интернет-банка. Позволяет независимое масштабирование и деплой.     |
| S4     | Мониторинг и логирование: отслеживание жизненного цикла заявок, метрики производительности, алертинг при сбоях.                                                                                     | Дополнительное: необходимо для SLA 99,9% — без мониторинга невозможно гарантировать доступность и быстро реагировать на инциденты. |
| S5     | Версионирование API новых микросервисов для обеспечения обратной совместимости при расширении.                                                                                                      | Дополнительное: планируется этап кредитования, потребуется расширение API без поломки существующих интеграций.                     |
| **+R** | **+ Ограничения (Restrictions / Constraints)**                                                                                                                                                      |                                                                                                                                    |
| +R1    | Безопасность: обязательное шифрование трафика (SSL/TLS) на сайте и в Интернет-банке при передаче чувствительных данных.                                                                             | Требование заказчика.                                                                                                              |
| +R2    | Регуляторное: обязательная очная идентификация новых клиентов (с сайта) в отделении банка.                                                                                                          | Законодательное ограничение (ПОД/ФТ, KYC). Банк не может принимать новых клиентов без личной проверки документов.                  |
| +R3    | Технологическое: использование Apache Kafka для асинхронного межсистемного взаимодействия.                                                                                                          | Требование заказчика                                                                                                               |
| +R4    | Технологическое: АБС масштабируется только вертикально (ограничение архитектуры Oracle PL/SQL).                                                                                                     | Жёсткое ограничение: невозможно горизонтально масштабировать АБС для обработки онлайн-нагрузки.                                    |
| +R5    | Организационное: функционал СМС (OTP) реализуется силами команды разработки банка, без привлечения подрядчика ядра Интернет-банка.                                                                  | Требование заказчика. Снижение зависимости от внешнего подрядчика.                                                                 |
| +R6    | Организационное: новые технологии должны быть совместимы с существующими платформами разработки; в банке должна быть экспертиза хотя бы на уровне языков программирования.                          | Требование заказчика. Ограничивает выбор стека при проектировании новых компонентов.                                               |
| +R7    | Технологическое: текущая платформа Интернет-банка (ASP.NET MVC 4.5 / .NET Framework 4.5) несовместима с Apache Kafka. Требуется адаптер или выделение нового микросервиса на совместимой платформе. | Архитектурно-значимое: следствие +R3 и +R6. Определяет необходимость микросервисного подхода (см. S3).                             |
